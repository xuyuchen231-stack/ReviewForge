# 九小时自动综述改进

在当前目录运行 `start_review_9h.bat`。无需先运行 init，无需手工填写 JSON 或逐节确认。

程序读取 workspace/review_en.tex（缺失时读取 original.tex），建立独立快照，自动设计论证、读取本地来源片段、建立比较记录、整小节改写并审查。重点是跨研究比较、差异解释、证据边界和有依据的结论，不以字数证明深度。只使用已取得的来源；缺失来源会写入 evidence_tasks，不能自动绕过机构登录或补造证据。

默认运行预算九小时，每单元最多两次科学修订访问（初稿加一次修订），预留最多40分钟用于全文组装、中文同步和编译。完成可处理任务或用尽轮次时可以提前结束，不空耗 API。预算在每次请求和账户切换前检查；网络读取超时不是严格的总墙钟时限，正在响应的请求或编译收尾可能略超预算。

限流账户暂时冷却十小时，优先使用其他可用账户，不归为永久耗尽。全部账户冷却时保存进度并等待预算允许的时间；冷却超过本次预算时保留未完成项。

用户明确授权多个账号额度切换时可设置 RF_ALLOW_BILLING_FAILOVER=1。HTTP402 的账号记录为 quota_unavailable，并立即尝试下一个已配置账号，暂时跳过该账号（默认10小时后可重新检查）；它与 HTTP429 的 temporary_rate_limit 分开记录，不永久标记耗尽。全部账号额度不可用时保留进度并按接口故障保护暂停；不充值、不创建账号。修改开关/程序文件不会热更新已经运行的旧进程。

每20秒显示状态。关闭或中断后运行同一入口可恢复；这会给予新的九小时预算，但保留已完成任务和已用科学审查轮次。中断中的尝试不消耗最终轮次。原稿改变或需要全新一轮时使用 `start_review_9h.bat --new-run`。不能同时运行两个实例。旧 resume_review_v4.bat 属于旧流程。

结果位于 workspace/autonomous_runs/<运行编号>/output；报告为同目录 reports/autonomous_result.json。原稿不覆盖；未通过或来源记录改变的单元保留原文并列入未完成清单。全文审查存在严重问题的候选稿不得进入交付稿。模型审查不代表作者批准、专家核验或可直接投稿。

`python autonomous_review.py --check` 仅检查本地输入，不调用模型。`--skip-translation` 可跳过中文同步。PDF生成取决于已有 TeX 环境和剩余时间。运行期间电脑需保持开启且联网。
故障保护：连续三次模型服务失败会保存并暂停，不消耗科学审查轮次。空响应会显示 finish_reason 和推理字符数（不记录推理内容），尝试其他账户；单篇提取/规划调用的回退预算最多180秒，整小节写作和审稿调用最多600秒（单路最多300秒），均受本轮总预算约束。
规划与提取明确使用准备阶段预算，正文大小不会将准备调用误判为600秒写作。兼容 DeepSeek 的准备请求默认关闭内部思考，使用准备模型（默认原主服务的审稿模型）；可用 RF_PREPARATION_MODEL 和 RF_PREPARATION_THINKING 显式调整。单次请求超时属于服务故障，只有整个运行预算耗尽才进入时间收尾；零个小节通过时不调用翻译或编译。
证据提取默认每批最多3篇、来源包合计最多36000 UTF-8字节，采用按论文隔离的片段编号，逐篇核验并保存。响应中缺失或无效的卡片只单独补一次，其余不重复提取。批大小可设 RF_EVIDENCE_BATCH_SIZE=1..4；超大来源包会报告需精确整理来源，不默默截断。旧版成功提取缓存继续使用。
完整流程修复：模型选择原文片段编号，程序填入逐字引文；每个小节保留独立比较记录，避免其他小节更新导致反复失效。审稿格式错误有限重试，已解决意见不再复活；暂停也组装本地已通过内容。英文先编译，翻译预留中文编译预算，旧译稿、PDF与对应报告一并隔离。续跑会重查证据阻塞任务，并记录更新的证据台账历史。

大单元验证：心跳显示 request_elapsed 和 request_budget。多篇研究的整小节写作不再与单篇证据提取共用180秒限制；重复引文仅在不增大请求且不丢失原文、字段、身份和定位信息时去重。

审稿引用校验：审稿回复引用的片段必须逐字存在于候选正文；不匹配时只有限重试审稿，不因此重写正文或消耗科学审查轮次。真实的内容缺陷仍进入修订流程。

模型仅返回推理且输出额度耗尽时，直接尝试已配置的备用模型，不逐个账户重复同一失败；账户不因此冷却或标为耗尽。服务失败时保留待审正文，恢复后先审稿。

整节审稿只接收唯一的当前候选稿，原稿与上一版仅用于写作修订。审稿默认输出预算为12000（兼容推理模型），可用 RF_AUTO_REVIEW_OUTPUT_TOKENS 配置；不是将超时或空响应视为通过。所有支持的引用命令使用同一保护检查；新引入的环境未闭合或嵌套错配在进入审稿前拒绝，旧损坏候选在组装时保留原文。

交付时使用本轮术语表和主题，并原样保护已列明的发酵微生物拉丁学名；普通英文段落仍须完成翻译。内嵌参考文献为作者式引用补充可核实的作者/年份标签；日期含歧义时不猜测。编译检查会阻止未解析的作者、年份、引用和缺字。

双栏导出不再自动回退为整篇单栏。图表使用可正常放置的跨栏浮动体，确实超宽的展示公式用 cuted 的 strip 局部跨栏，保留公式源码；仅剩不超过3pt的垂直溢出时才有限调整正文高度。仍未通过就报告，不删除公式或缩小到难以阅读。原导出及修改记录保存在 reports/layout_original_english.tex 和 reports/layout_adaptation.json。本机已配置 cuted；其他环境需提供该标准 LaTeX 包。PDF预览和实际阅读顺序检查依赖 requirements-preview.txt。

导出时仅对明确、无歧义的相同 DOI 合并重复条目，记录引用键映射；注释或多个不同 DOI 不作为合并依据。数字引用最终按 PDF 的双栏/跨栏阅读顺序核查，并展开合并编号区间；重复引用复用原编号。重排失败或预算不足时保留上一次成功的源文件、PDF 和编号映射，不声称核查通过。作者—年份样式保留原有排序。

本机已有 publication_figure_plan.json 时，自动导出可据其中经核对的来源和章节插入概念图，不发模型请求。图件必须区分示意与实验数据；未提供图件计划时不编造数据填数。计划随本项目快照保留。英文编译与引用顺序通过后生成只包含 main.tex 及所引用资源的 Overleaf ZIP，编译器选 XeLaTeX。详见仓库 docs/PUBLICATION_EXPORT_ZH.md。

续跑会重新核对已通过稿件的原稿、证据契约、候选文本和结构；失效或损坏缓存重新进入队列，不能一直停在“完成”状态。仍有未完成任务时，续跑也重新开放跨节审查预算。组装与跨节审查采用相同的候选有效性检查。来源偏移、片段编号等内部记录不进入论文正文；原始证据仍在台账中保留。

跨节审查按有重叠的窗口分组，每组正文最多32000字符，完整覆盖各单元，并另外比较全局开头/结论片段。已验证的分组结果按输入、提示词和模型策略保存；断线后重用未变化的成功结果，新增严重问题立即阻止相应候选交付，不因后续组失败而丢失。报告明确记录完成组数和完整/片段范围，不能将部分成功冒充全文审查通过。

跨节一致性任务默认采用审稿模型，可用 RF_COHERENCE_MODEL 单独指定；逐节证据审稿仍采用 RF_REVIEWER_MODEL。兼容 DeepSeek V4 的跨节请求默认显式设置 thinking=disabled，避免内部推理耗尽输出空间；可用 RF_COHERENCE_THINKING=enabled 恢复该任务的深度模式，并用 RF_COHERENCE_REASONING_EFFORT=low/high/max 调节。逐节写作和证据审稿保持原思考设置，输出判定与引用检查均不放宽。报告记录实际模型、请求的模式及返回的推理字符数；不能把同模型检查宣称为独立专家审稿，也不能假定所有网关都会遵从可选参数。

跨节审查返回片段编号，由程序填回原文和相关单元上下文，避免模型抄错公式导致审查失败；未审原稿与已通过候选明确区分。修订仅针对未解决意见，保留已有证据与有效比较。新增公式引用必须指向全文已有且唯一的有效标签；修订、审稿请求在补齐所有上下文后再次检查长度，超限保存并报告，不默默截断证据。

内容深度更新（2026-10-26）：每个实质性小标题均需展开具体问题、可比较的研究发现、差异或不可比的原因、验证边界和有条件的判断。公式之后需解释假设、所学量及适用/失效边界；不以字数、段数、引文数量作为质量标准，也不编造结果补篇幅。过渡段仍按实际过渡功能评估。

逐节审稿使用现有五项准则，同时检查引据是否覆盖每个有正文的小标题，不能只评一段便批准整节。模型可返回候选片段编号，由程序填入逐字原文；伪造编号和引文冲突被拒绝。片段覆盖只证明审查范围，科学深度仍由证据审稿判断。修订仅重发可行动的问题，不重复整套旧准则引句；完整审稿记录始终保存在本地。

更新后运行 `start_review_9h.bat` 即续跑九小时预算：保留已有证据提取、规划和候选稿，旧通过稿按新深度契约重新核验。通常不要加 `--new-run`，以免建立新任务并重复提取。更新程序本身不会自动启动九小时任务。

添加 APIMaster 备用接口：运行 `python configure_apimaster.py`，隐藏输入密钥，再从账号实时返回的模型列表中选择支持 chat/completions 的文本模型。接口为 https://apimaster.ai/v1，模型 ID 不沿用其他平台的 `:free` 名称；使用 APIMaster 自己的额度和价格。配置保存在用户目录 `.reviewforge/providers.json`，不进入仓库，不覆盖原有主服务或其他备用服务。配置过程只读取模型列表，不发送生成请求；读取成功不代表已验证模型生成能力。

下次启动时读取备用配置；正在运行的进程不会自动加载或被中断。主服务失败时在同一请求总预算内尝试备用服务，账号冷却仍按接口地址和密钥分别记录。报告记录实际服务及模型；所有服务不可用时保存并按原故障保护暂停。切换不会自动增加本轮总时间或预算。

## 2026-10-26：按耗时日志调整的执行策略

正文写作初始输出预算为10000 tokens，审稿为12000；允许模型提前结束，不强迫消耗额度。英文写作仍直接输出 LaTeX，定稿后单独翻译，未引入双语大 JSON 或 XML 包装。审稿继续选片段编号，代码回填原文，不使用可能混淆公式/否定词的模糊匹配。

运行目录下 source_cache 以完整问题、比较维度、实际来源片段和提取策略指纹保存证据卡，可跨单元复用相同请求。问题、维度或来源改变就重新核验；单纯 source_id 相同不够。逐篇成功卡片立即保存，后续断网不清空缓存。reports/*_extraction_stats.json 记录缓存命中、请求来源数和局部补救次数。

调度优先使用准备好的证据、覆盖准备量较小的单元；服务失败单独计数并后移，不退还科学轮次后马上反复选择同一个大单元。相同候选、证据契约和未解决意见重复被拒绝时标记 blocked_no_increment，不靠反复抽取审稿结果来获得通过；证据契约更新后重新开放。小文风建议在所有实质准则通过时不要求重写，证据/逻辑缺陷仍不能自动放行。

核心小节有至少3篇供用研究及全文/全文片段时，给出机理演进、横向比较、批判性结论的展开契约和600–1000英文词的参考范围。保留原有更长的有效内容，允许各论证功能跨多个自然段；不强制每个小标题写3段或800词，也不强迫摘要缺少的数字、工况和实验细节。字数只作提示，不能代替审稿。

本机 providers.json 已可设置 preferred_provider=apimaster，使已配置的 GPT 用于正文写作/逐节审稿；准备和跨节一致性默认优先原主服务的 DeepSeek 非思考路线，以减少重复长推理。可用 RF_PREPARATION_PROVIDER 或 RF_COHERENCE_PROVIDER 显式指定其他已配置服务。服务、模型和临时冷却独立，备用服务保留。每个服务和模型均为后续备用路线预留时间。

observed_token_usage 只累计程序取得非空成功回复时接口返回的 prompt_tokens/completion_tokens/total_tokens，并区分提供/未提供 usage 的调用。空内容、报错、断网和历史请求可能计费但不包含在这个合计中，因此它是成功回复的部分用量，不能当作完整账单或总消耗；累计 calls 也不是本次重跑新消耗的调用数。

版面报告包含 overflow_details（方向、pt数、日志提供的起止行）和 severe_overflow_count；小于5pt也仍列为溢出，缺字/引用异常继续阻止版面通过。PDF生成不等于布局合格，日志无警告也不保证视觉无误。原公式不做正则转换、自动缩小或补造换行。

figure_templates.py 接受显式 JSON 绘图规格：topology 使用 Graphviz 自动布局并导出 DOT/PDF/PNG；bar 使用固定 Matplotlib 样式导出矢量 PDF 和300dpi PNG。数据须有单位、可比较任务和逐项 source_ids；来源编号的语义真实性仍需核验。绘图依赖为可选 requirements-figures.txt，Graphviz 缺失时只保存 DOT、报告 UNAVAILABLE；不会冒称生成了图。旧图与清单先隔离，防止把旧输出当成当前结果。程序不执行模型生成的绘图代码，也不自动重画原稿现有图。

实际验证范围：三篇真实来源一次批提取4.9秒且逐篇校验通过；恢复同一请求命中3篇缓存、零模型调用。独立快照中 GPT-6.1 Sol 写作98.7秒、GPT-6 Astra审稿39.9秒，第4单元约1031英文词且通过模型审稿，完整跨节分组恢复完成，英文编译/版面PASS。它不是整篇58单元完成证明，也不承诺固定倍数提速或期刊录用。
# TokenHarbor 免费账号周期与本次质量更新

启用 `RF_TOKENHARBOR_PRIME_ACCOUNTS=1` 后，启动时只对尚无成功记录且当前可用的 TokenHarbor 免费账号发出最小请求，启动预算最多 60 秒；已有成功观察的账号跳过。免费调用使用 `:free` 模型，不通过此步骤调用备用付费平台。账号按配置顺序使用，免费周期耗尽后暂存恢复时间，到期可以重试，不作永久禁用。

本机周期台账为 `%USERPROFILE%\.reviewforge\tokenharbor_cycles.json`，仅存凭据指纹；成功观察不一定是平台真正首次使用。后台已知刷新时间可以作为周期依据，安全余量单独保存，不随重启重新倒计时。普通请求频率限制仍按临时冷却处理。

可用 `python account_cycles.py --workspace workspace --backfill` 从已有日志补充最早成功观察并生成本机账号报告；该命令不发模型请求。`--initialize` 才明确执行尚需初始化的免费账号请求。备份/迁移程序时保留本机台账，账号顺序变更前不要重新按旧日志槽位补填历史。

数字制手工参考文献现在在导出时按正文首次引用排列。写作与审稿新增段落逆向提纲、反证、比较条件和具体缺口检查；旧深度结论需要按新策略重新核查，已提取来源可继续复用。详细取舍见仓库 `docs/SKILL_ADOPTION_ZH.md`。运行中的 Python 进程不热加载更新，下一次启动才使用新逻辑。
