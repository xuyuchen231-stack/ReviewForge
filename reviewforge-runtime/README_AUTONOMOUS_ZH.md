# 九小时自动综述改进

在当前目录运行 `start_review_9h.bat`。无需先运行 init，无需手工填写 JSON 或逐节确认。

程序读取 workspace/review_en.tex（缺失时读取 original.tex），建立独立快照，自动设计论证、读取本地来源片段、建立比较记录、整小节改写并审查。重点是跨研究比较、差异解释、证据边界和有依据的结论，不以字数证明深度。只使用已取得的来源；缺失来源会写入 evidence_tasks，不能自动绕过机构登录或补造证据。

默认运行预算九小时，最多每单元三轮，预留最多40分钟用于全文组装、中文同步和编译。完成可处理任务或用尽轮次时可以提前结束，不空耗 API。预算在每次请求和账户切换前检查；网络读取超时不是严格的总墙钟时限，正在响应的请求或编译收尾可能略超预算。

限流账户暂时冷却十小时，优先使用其他可用账户，不归为永久耗尽。全部账户冷却时保存进度并等待预算允许的时间；冷却超过本次预算时保留未完成项。

每20秒显示状态。关闭或中断后运行同一入口可恢复；这会给予新的九小时预算，但保留已完成任务和已用科学审查轮次。中断中的尝试不消耗最终轮次。原稿改变或需要全新一轮时使用 `start_review_9h.bat --new-run`。不能同时运行两个实例。旧 resume_review_v4.bat 属于旧流程。

结果位于 workspace/autonomous_runs/<运行编号>/output；报告为同目录 reports/autonomous_result.json。原稿不覆盖；未通过或来源记录改变的单元保留原文并列入未完成清单。全文审查存在严重问题的候选稿不得进入交付稿。模型审查不代表作者批准、专家核验或可直接投稿。

`python autonomous_review.py --check` 仅检查本地输入，不调用模型。`--skip-translation` 可跳过中文同步。PDF生成取决于已有 TeX 环境和剩余时间。运行期间电脑需保持开启且联网。
故障保护：连续三次模型服务失败会保存并暂停，不消耗科学审查轮次。空响应会显示 finish_reason 和推理字符数（不记录推理内容），尝试其他账户；单篇提取/规划调用的回退预算最多180秒，整小节写作和审稿调用最多600秒（单路最多300秒），均受本轮总预算约束。
规划请求已拆为论证设计和逐篇证据提取，planning_cache 保存每篇成功结果。单次请求超时属于服务故障，只有整个运行预算耗尽才进入时间收尾；零个小节通过时不调用翻译或编译。响应正文只有空白时记录安全元数据并尝试其他账户。
单篇证据提取采用编号维度，禁止添加额外维度，并限制字段说明与引文长度；初始输出预算为6000 tokens，截断时明确打印原因后有限重试。旧版成功提取缓存可以继续使用。
完整流程修复：模型选择原文片段编号，程序填入逐字引文；每个小节保留独立比较记录，避免其他小节更新导致反复失效。审稿格式错误有限重试，已解决意见不再复活；暂停也组装本地已通过内容。英文先编译，翻译预留中文编译预算，旧译稿、PDF与对应报告一并隔离。续跑会重查证据阻塞任务，并记录更新的证据台账历史。

大单元验证：心跳显示 request_elapsed 和 request_budget。多篇研究的整小节写作不再与单篇证据提取共用180秒限制；重复引文仅在不增大请求且不丢失原文、字段、身份和定位信息时去重。

审稿引用校验：审稿回复引用的片段必须逐字存在于候选正文；不匹配时只有限重试审稿，不因此重写正文或消耗科学审查轮次。真实的内容缺陷仍进入修订流程。

模型仅返回推理且输出额度耗尽时，直接尝试已配置的备用模型，不逐个账户重复同一失败；账户不因此冷却或标为耗尽。服务失败时保留待审正文，恢复后先审稿。

整节审稿只接收唯一的当前候选稿，原稿与上一版仅用于写作修订。审稿默认输出预算为12000（兼容推理模型），可用 RF_AUTO_REVIEW_OUTPUT_TOKENS 配置；不是将超时或空响应视为通过。所有支持的引用命令使用同一保护检查；新引入的环境未闭合或嵌套错配在进入审稿前拒绝，旧损坏候选在组装时保留原文。

交付时使用本轮术语表和主题，并原样保护已列明的发酵微生物拉丁学名；普通英文段落仍须完成翻译。内嵌参考文献为作者式引用补充可核实的作者/年份标签；日期含歧义时不猜测。编译检查会阻止未解析的作者、年份、引用和缺字。

若双栏导出仅存在排版溢出、没有未解析引用或缺字，会有限尝试单栏导出；如只剩不超过3pt的垂直溢出，再将正文高度增加3pt。数学、引用、原稿保持不变，原导出稿及调整记录保存在 reports/layout_original_english.tex 和 reports/layout_adaptation.json。仍未通过时如实报告，不循环改写数学。PDF预览依赖可选的 requirements-preview.txt。

续跑会重新核对已通过稿件的原稿、证据契约、候选文本和结构；失效或损坏缓存重新进入队列，不能一直停在“完成”状态。仍有未完成任务时，续跑也重新开放跨节审查预算。组装与跨节审查采用相同的候选有效性检查。来源偏移、片段编号等内部记录不进入论文正文；原始证据仍在台账中保留。

跨节审查按有重叠的窗口分组，每组正文最多32000字符，完整覆盖各单元，并另外比较全局开头/结论片段。已验证的分组结果按输入、提示词和模型策略保存；断线后重用未变化的成功结果，新增严重问题立即阻止相应候选交付，不因后续组失败而丢失。报告明确记录完成组数和完整/片段范围，不能将部分成功冒充全文审查通过。

跨节一致性任务默认采用写作模型，可用 RF_COHERENCE_MODEL 单独指定；逐节证据审稿仍采用 RF_REVIEWER_MODEL。所有实际模型记录在报告中，不将相同模型的检查宣称为独立专家审稿。兼容的 DeepSeek V4 路由可用 RF_COHERENCE_REASONING_EFFORT=low/high/max 控制该任务的推理强度（默认low）；它不改变逐节审稿设置，也不替代输出完整性检查。
